# ApocaPocket — North Star Spec

> This document defines what ApocaPocket is, what it is not, and why every decision must pass through this filter first.

---

## 1. Core Identity

ApocaPocket is an **offline survival decision tool**.

It is:
- A field reference for real-world disruption

It is **not**:
- A wiki
- A prepper novelty
- Entertainment
- Fantasy apocalypse cosplay

**Real-world use cases:**
- Power outage
- Wildfire smoke
- Civil unrest
- Heat wave
- Injury
- Water boil advisory
- Getting stranded

If something goes wrong, this device becomes useful.

---

## 2. The Emotional Target

When someone uses it, they should feel:
- **Calm**
- **Guided**
- **Less alone**
- **Capable**

Not:
- Overwhelmed
- Lectured
- Reading an essay
- Scrolling forever

The experience should feel like: **"Okay. I can handle this."**

---

## 3. The 10-Second Rule

Every entry must pass this test:

> Within 10 seconds, the user must know:
> 1. Is this relevant to me?
> 2. What should I do first?

If it doesn't pass that test, it fails.

---

## 4. Content Architecture Standard

Each cluster must follow this structure:

### A. Gateway Overview (Required)
- Short
- Decision-oriented
- Compares methods
- Directs to sub-entries

Example (Fire):
- "Need heat fast?" →
- "No tools?" →
- "Wet conditions?" →

This reduces cognitive load under stress.

### B. Technique Modules
Each module:
- 8–12 cards
- Clear section headers (≤22 chars)
- No tables
- Flat bullets
- Practical steps
- Failure signs
- When to stop

### C. Troubleshooting
Always include:
- What usually goes wrong
- What it looks like
- How to correct it

This is what separates a toy from a field tool.

### D. Practice Benchmarks *(optional but powerful)*
- "If you can't do this in 5 minutes, practice."
- "Should produce X result."
- "Takes 300–500 calories."

This builds real-world competence, not just reference knowledge.

---

## 5. UI Philosophy

The device must feel:
- **Minimal**
- **Intentional**
- **Calm**
- **Durable**

No decorative nonsense.
No excessive scrolling.
No unnecessary animation.

It should feel closer to:
- A calculator
- A field radio
- A compass

Not a smartphone.

---

## 6. Stress Navigation Principle

Navigation must assume the user is:
- Cold
- Hungry
- Tired
- Anxious

So:
- Short headers
- Clear language
- No jargon
- No nested logic trees inside paragraphs

Every card must answer: **"What do I do next?"**

---

## 7. Cool Factor

It should feel:
- Serious
- Functional
- Legit
- Thoughtful

Not:
- Tactical cosplay
- Military LARP
- Edgy apocalypse branding

The coolness comes from: **"This is actually useful."**

Reference energy:
- Game Boy
- Field manual
- NASA checklist

Clean. Purposeful.

---

## 8. Hardware Philosophy

Keep it:
- Offline-first
- Battery efficient
- Durable
- Repairable
- Modular

No feature should exist just to be impressive.

Sensors should only exist if they:
1. Solve a real problem
2. Improve decision speed
3. Increase survivability

If not — leave it out.

---

## 9. Audience

**Primary users:**
- Hikers
- Campers
- Power outage preppers (normal people)
- Parents
- People in wildfire regions
- People who think "what if?" sometimes

**Not exclusively:**
- Hardcore survivalists
- Tactical fantasy crowd

> If it works for normal people, it works for everyone.

---

## 10. The Final Product Test

Ask this before shipping any feature or entry:

> If I hand this to a random adult during a 3-day blackout, a boil water advisory, or a broken-down car — would they say **"This is helpful"** or **"Oh that's kinda neat"**?

It must hit **"helpful."**

---

## The Non-Negotiables

- Offline
- Clear
- Decision-first
- Stress-tested
- No wasted words
- No broken formatting
- No essay entries
- No clutter

---

## The Filter

Every time you:
- Add a feature
- Write an entry
- Consider a sensor
- Redesign the UI

Ask: **Does this support the North Star?**

If not — cut it.

---

*This spec is permanent. It does not expire. It does not bend for convenience.*
